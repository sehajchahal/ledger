# Ledger

`CLAUDE.md` is a pointer to this file. Everything below is the project's own
rules; the block above is generated by Next and will reappear if deleted.

## What this is

**Ledger** measures whether AI assistants recommend a brand, explains why they
don't, and proves whether a fix changed the answer.

Eleven tools already report that you were mentioned 38 times. None of them close
the loop. Ledger's reason to exist is the verification loop: ship a fix, wait,
re-run the same prompts, and show the delta — including when the delta is
negative. Every product decision resolves against that. If a feature does not
help someone measure, diagnose, fix, or prove, it does not get built.

Target customer is the small and mid-sized business that the enterprise tools
price out and overwhelm, plus the agencies managing several of them. A two-person
marketing team needs to know the one thing to do on Monday, not forty findings.

Read `DESIGN.md` before writing any UI. Its "what this must not look like" list
is binding.

## Stack

- Next.js 16 (App Router, Turbopack), TypeScript strict, React Server Components
  by default. `params` and `searchParams` are Promises; use the generated
  `PageProps<'/route'>` / `LayoutProps<'/route'>` / `RouteContext<'/route'>`
  helpers rather than hand-written prop types.
- Tailwind v4. Tokens live in `@theme` in `app/globals.css` and are used as named
  utilities (`bg-paper`, `text-signal`). There is no `tailwind.config.ts` — v4
  does not need one. No arbitrary color values in components: if you are typing
  `text-[#...]`, stop.
- Drizzle ORM against Postgres. Migrations in `drizzle/`, never hand-edited after
  they run. `npm run db:start` boots a local cluster in `.pgdata` on port 5433.
- `next/font` for all three families. No external font CDN.
- Vitest for unit tests. The parser is the part that must be tested; UI is not.

## Layout of the code

```
app/                 routes. /brands/[brandId]/* is the product, / is the landing page
components/          shared UI. PresenceStrip lives here.
config/models.ts     job name -> model id. The only place a model id is written.
lib/ai/router.ts     runJob(jobName, input). The only place a model is called.
lib/ai/providers/    perplexity.ts, anthropic.ts, fixture.ts
lib/parse/           mentions.ts, metrics.ts. Deterministic. No model calls, ever.
lib/probe/run.ts     one implementation of what a run means
lib/actions/         generate.ts (fixes), verify.ts (the loop), jsonld.ts
lib/db/              schema.ts, index.ts, queries/
scripts/             seed.ts, seed-history.ts, run-probe.ts, parse-run.ts, verify-actions.ts
```

Three rules about this structure:

1. **Model ids appear only in `config/models.ts`.** Not in a route, not in a
   script, not inlined "just for now". Swapping a model is a one-line change in
   one file.
2. **`lib/parse/` never calls a model.** Mention detection is string matching and
   it must be reproducible for the same input forever, because verification
   deltas are computed from it. A metric that drifts because a model felt
   different today is not a metric.
3. **A run is either `full` or `verification`.** Verification re-checks ask only
   the prompts one action touched, so they must never be picked up as the
   brand's latest measurement. Every "latest completed run" query filters
   `kind = 'full'`.

## How data is treated

This is the part that separates the product from its competitors, so it is
enforced in code, not left to judgement.

- A **measurement** is a stored answer, a parsed mention, or a number derived
  from those. Rendered in mono. Stated without hedging.
- An **estimate** is anything inferred, attributed probabilistically, or
  projected. Rendered with amber and labelled in adjacent mono text. Never
  rounded up into a measurement.
- **Generated text** is anything a model wrote — a suggested fix, a diagnosis, a
  draft. It is prose, never mono, and it is always presented as a proposal a
  human approves.
- **Fixture answers are not measurements.** With no API key set, probes are
  synthesised locally and carry a `fixture/` model prefix. Every surface that
  shows them must label the run as demo data.
- Never state or imply that a change will cause a model to mention the brand. It
  might not. Copy says "we re-check and report the change", not "we get you
  mentioned".
- Sample size is shown next to any percentage from under 100 observations. A 67%
  built from 3 probes says `67% · 2/3`.
- A failed probe stores nothing for that probe index rather than an empty answer.
  Absence of a measurement is not a measurement of absence, and every metric
  divides by the probes that actually returned.
- Nothing is published, emailed, or sent to a customer's site without a human
  approving it. Ledger generates; the user ships.

## Copy rules

The copy is half the product. It is what makes it read like a tool built by
someone who has done the work rather than a landing page generator.

- Sentence case everywhere. Headings, buttons, labels, table headers, email
  subjects.
- Plain verbs. Check, run, fix, prove, ship, compare. Not leverage, empower,
  unlock, supercharge, revolutionize, transform, elevate, harness, seamless,
  effortless, robust, cutting-edge, game-changing, next-generation.
- No exclamation marks. None. Not in success toasts, not in the email.
- No emoji anywhere.
- Second person, present tense. "You're not in this answer", not "Your brand has
  not been identified in this response."
- Say the number. "Mentioned in 4 of 25 prompts" beats "Low visibility detected".
- Bad news is delivered at full volume. A dropped mention is not "an
  opportunity". A negative delta is not "a learning". Write it the way you would
  say it to someone paying you.
- No rhetorical questions as headings. No "Here's the thing."
- Error and empty states get the same care as the hero. One line on what
  happened, one on what to do.

Test for any sentence: could this appear verbatim on a competitor's site? If
yes, rewrite it.

## Conventions

- Server Components fetch data directly through `lib/db/queries/`. Client
  Components are marked and kept small — interactivity only, no data fetching.
- Server Actions for mutations. No API routes except the public check endpoint,
  the health check, and signed email approval links.
- Every enqueue path checks `lib/limits.ts` before doing work.
- Errors are logged with structured context and surfaced to the user in plain
  language.
- Dates stored UTC. Raw SQL through `db.execute` returns timestamps unparsed on
  some driver paths — coerce with `new Date()` rather than assuming.
- Rates persisted as `numeric(6,4)`. Quantize both sides to 4 decimals before
  subtracting, or 2/3 minus 2/3 comes out negative and flips a delta's sign.
- No `any`. No `@ts-expect-error` without a comment saying what will remove it.
- Focus is `2px solid ink` at `2px` offset, from a global `:focus-visible` rule.
  Never add `focus:outline-none` — it suppresses `:focus-visible` too.
- Grid and flex children that contain wide content (tables, code blocks) need
  `min-w-0`, or they push the page into horizontal overflow instead of scrolling
  inside their own container.

## Working agreement

- Follow the phase order in `BUILDSCRIPT.md`. Run the verification step at the
  end of a phase before starting the next one.
- When a phase's instruction and this file disagree, the phase wins for
  behaviour and this file wins for style.
- Do not add dependencies for things the platform does. No date library for
  formatting a timestamp, no chart library for the presence strip, no UI kit.
